# 审核、写回与交付

## 写前审查

确认目标文档、章节或块，以及用户允许新建、覆盖、追加还是局部更新。新建时确认需要的标题和创建位置；已有上下文足够就直接使用，不重复请求许可。

保存修改范围相关的正文、结构、表格、资源引用和受保护内容基线。用户要求不改某章时，整章及其嵌入资源属于保护范围，不能只跳过可见文字。资源或评论信息取不到时记录缺口，不声称已完整备份。

对照来源审查本地稿。格式任务逐字符核对显示内容，内容任务按授权核对事实与删改，精简任务检查关键限制。表格的预期最优位置应与实际草稿一致。

## 最小必要写入

优先修改指定块或范围，避免为了调整几个字重重建整个文档。写前发现版本变化，先重读并重新核对；平台支持版本条件时使用它。定位不确定时不要盲目覆盖。

写入分批时保留已成功的范围与响应状态。部分失败或结果不明时先读当前目标，确定已经发生什么，再决定重试；避免重复创建和重复追加。高风险门禁按工具当前要求处理，不通过静默加参数绕过。

## 回读与视觉

核对实际内容、数字显示、顺序、链接、图片、附件和保护范围；按编辑方式单独验证评论、锚点与修订。文字一致不能证明这些资源完整。

样式核对标题层级、富文本片段、整格背景、合并结构、对齐与列宽。指标表检查预期粗体集合与实际集合相等，不能只确认“没有错标”而漏掉应该标出的值。

能访问飞书页面时检查实际阅读尺寸：折行、数字截断、提示块密度、表格宽度、底纹和对比度。只检查过草稿、XML 或 API 时，明确未验证最终视觉；浏览器未登录不等于 CLI 未授权，不为视觉检查重置已有连接。

## 交付

提供真实创建或更新的飞书链接；只做本地稿时提供本地文件。说明已改范围、实际检查和剩余限制。未成功写入的部分直说，避免把“生成了草稿”表述为“已更新文档”。

内部协作、模型分工、认证诊断与排版建议默认不写入读者正文，除非用户明确要这类操作文档。
