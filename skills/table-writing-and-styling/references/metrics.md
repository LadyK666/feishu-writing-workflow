# 指标与大表

## 比较前先划定范围

记录指标名称、方向、单位、子集或条件、统计量，以及来源中任何会影响可比性的限制。覆盖率与样本量通常是比较条件；除非任务明确将其定义为目标指标，不参加性能排名。

不同测试集、硬件、预算、样本口径不能默认混排取极值。有些局部范围不清楚时，先完成已明确部分，不取消所有加粗。

## 逐指标选择强调

- 对 ↑ 指标取该范围内最大有效值，对 ↓ 指标取最小有效值。
- mean、median、p95 独立判断；一个方案不需要同时赢下所有统计量。
- 精确并列全部加粗。不要私设浮点容差，或把数值接近视为统计并列。
- `—`、空值、NaN、非有限值和失败记录保留原显示，不当成通常排名中的零。
- 结果含区间、误差项、显著性符号或多个评价口径时，按来源定义解释。比较规则不明时不要只挑其中一个数字强行排名。
- 本地比较不会改变显示精度。`0.50` 与 `0.5` 可以数值相等，但各自保留原字符串。

只标当前比较范围内的最好值；“最优”不等于已证明的 SOTA。不要新增显著性、因果、速度倍率或百分比收益，除非任务授权且计算依据充分。

同一格写成 `mean / median / p95（覆盖）` 时，对每个数值片段独立应用字重。整段加粗会误导读者以为三个统计量都获胜。

## 密集数据的阅读层次

先用表头与浅底纹揭示分组，再让粗体指向真实优值。若几乎每行都有最优值，允许自然呈现，不为控制粗体数量而漏掉并列或胜出值；可在允许重组时拆成更清楚的分组。

仅当获准增加文字时，在表旁用一至三句说明：

1. 表比较什么，服务哪个问题。
2. 原文已有的主要结论；若获准描述直接比较结果，可简述对应现象。
3. 会改变理解的范围、覆盖或限制。

区分“原文已有结论”和“从表直接观察到的比较”。若用户只允许使用原文结论，不自行补第二类结论。没有依据就不写结果句，不能将目的改写为已证实的结论。

## 验证

以行标识、子集、指标、统计量定位每个预期粗体片段，核对实际写入位置：预期集合与实际集合应相等。只检查“没有错误粗体”会漏掉“完全没做最优标记”。来源数据、显示值和覆盖范围也要单独核对。
